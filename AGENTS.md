# Marketplace course project

## Working rules

- The student decides application scope and substantive report wording. Ask when a choice affects either, and disclose any assumptions you make.
- Check the command, its side effects, and its target environment before running it. Always specify the working directory.
- The user handles commits and deployment. Ask for explicit permission before deleting or moving any file, directory, data, or other resource.
- After editing Typst, compile from `main.typ` with `typst compile main.typ`. You may update `main.pdf` without a separate notice. Report compilation problems and material limitations.
- The student permits fixes to the linked `bsuir-core` library when needed. Report any changes to that library.
- Keep plans and notes in `docs/agent-notes/`. Record important style rules, accepted decisions, and open questions in the relevant Markdown file as work progresses. Update the links below when a note is added or renamed.

## Report

- Write concise, impersonal Russian. Keep open design questions in the notes. Include technical details the student has agreed to and can explain.
- Use the document's normal typeface for data types and identifiers. Do not use Typst backtick markup to display them in monospace.
- Use the assignment sheet for the report structure and СТП 01-2024 for formatting. Read the report guide before editing Typst.
- Use Typst labels and references for sources, figures, tables, and appendices. Use `--` for an en dash, `- ` for a simple list item, and a single hyphen inside words.
